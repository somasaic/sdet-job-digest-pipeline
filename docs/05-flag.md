# Step 5 — Flag

**Goal:** catch the practical problems a fit/ATS score alone won't — dead postings, wrong employment type, logistics friction — before they waste application time.

## Staleness

Every posting's stated date (where the source provides one) gets checked against today. Anything older than ~21 days gets tagged as stale and dropped from the daily recommended count, regardless of how well it otherwise scores — it can still be shown, but clearly marked, never presented as a fresh recommendation.

This rule exists because of a specific incident: a "remote" posting dated six months earlier was still surfacing in search results as if it were live and actively hiring. A great Fit/ATS score on a six-month-old ghost listing is worse than useless — it's actively misleading.

## Contract vs. permanent

Employment type gets treated as its own policy field, same tier as compensation or location — not a footnote. Contract-only or freelance roles get an explicit tag and don't count toward the daily recommended tally by default, though an exceptional fit can still surface as a clearly-marked backup. Permanent/full-time is the default assumption unless the JD states otherwise.

## Logistics friction

Flagged separately from skill fit, not folded into the score: in-office-only when I want remote/hybrid, unusual timezone-overlap requirements, and suspiciously low compensation for the role level. None of these alone disqualify a posting — they're information I need before deciding to apply, not a reason the system decides for me.

## Result, 15 days

- **15 stale postings caught**, including the six-month-old ghost listing that prompted the rule
- Contract-only roles tagged and excluded from the default recommended count rather than silently blending in with permanent options
- Logistics friction called out on every posting where it applied, kept visibly separate from the skill-fit judgment
